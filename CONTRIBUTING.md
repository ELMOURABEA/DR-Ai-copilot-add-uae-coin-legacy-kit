# Contributing Guidelines

Thank you for your interest in contributing to the UAE 1972-2025 Commemorative Coin Legacy Kit project.

## 🌟 Overview

This is an official project for the United Arab Emirates government. All contributions must meet the highest standards of quality, accuracy, and cultural sensitivity.

## 🔍 Before You Contribute

### Understanding the Project
1. Read the [README.md](README.md) thoroughly
2. Review the [PUBLISHING_GUIDELINES.md](PUBLISHING_GUIDELINES.md)
3. Familiarize yourself with the [REVIEW_CHECKLIST.md](REVIEW_CHECKLIST.md)
4. Understand the project's purpose and significance

### Prerequisites
- Respect for UAE culture and values
- Attention to detail and accuracy
- Ability to work with bilingual content (Arabic & English)
- Understanding of government submission requirements

## 📝 How to Contribute

### Types of Contributions

We welcome the following types of contributions:

1. **Content Improvements**
   - Corrections to text or translations
   - Enhanced descriptions or documentation
   - Additional historical context or information

2. **Technical Updates**
   - Bug fixes in workflows or scripts
   - Improvements to documentation formatting
   - Updates to technical specifications

3. **Design Assets**
   - High-resolution images
   - Design documentation
   - Visual improvements

4. **Translations**
   - Improvements to Arabic translations
   - Ensuring cultural accuracy
   - Bilingual consistency checks

### Contribution Process

#### 1. Create an Issue First
Before making changes:
- Check existing issues to avoid duplication
- Create a new issue describing your proposed contribution
- Wait for feedback from maintainers
- Discuss the approach if it's a significant change

#### 2. Fork and Branch
```bash
# Fork the repository on GitHub
# Clone your fork
git clone https://github.com/YOUR-USERNAME/DR-Ai-copilot-add-uae-coin-legacy-kit.git

# Create a feature branch
git checkout -b feature/your-feature-name
```

#### 3. Make Your Changes
- Keep changes focused and minimal
- Follow existing code/documentation style
- Ensure bilingual updates (Arabic & English) when applicable
- Test your changes thoroughly

#### 4. Self-Review Using Checklist
Before submitting, review your changes against the [REVIEW_CHECKLIST.md](REVIEW_CHECKLIST.md):
- [ ] Content is accurate and factually correct
- [ ] No spelling or grammatical errors
- [ ] Bilingual content is consistent
- [ ] Changes respect UAE cultural values
- [ ] Technical details are verified
- [ ] All links and references work correctly

#### 5. Commit Your Changes
```bash
# Stage your changes
git add .

# Commit with a descriptive message
git commit -m "Brief description of your changes"

# Push to your fork
git push origin feature/your-feature-name
```

#### 6. Submit a Pull Request
- Create a pull request from your fork
- Provide a clear description of changes
- Reference the related issue
- Include before/after examples if applicable
- List any breaking changes or considerations

## ✅ Review Process

### What Happens After Submission

1. **Initial Review** - Maintainers will review your PR within 3-5 business days
2. **Feedback** - You may receive requests for changes or clarifications
3. **Content Review** - Bilingual content will be reviewed by language experts
4. **Technical Review** - Technical changes will be validated
5. **Cultural Review** - Content will be reviewed for cultural appropriateness
6. **Approval** - Once approved, your PR will be merged

### Review Criteria

Your contribution will be evaluated based on:
- **Accuracy** - Is the information correct and verified?
- **Quality** - Is the content well-written and professional?
- **Cultural Sensitivity** - Does it respect UAE values and culture?
- **Completeness** - Are both Arabic and English versions provided?
- **Compliance** - Does it meet government submission standards?

## 🚫 What NOT to Contribute

Please do not submit:
- Unverified information or speculation
- Content that doesn't respect UAE culture or values
- Changes to official specifications without authorization
- Copyrighted material without proper licensing
- Low-quality or unprofessional content
- Breaking changes without discussion
- Personal opinions or controversial statements

## 📐 Style Guidelines

### Documentation
- Use clear, professional language
- Write in complete sentences
- Use proper markdown formatting
- Include both Arabic and English for all content
- Keep line length reasonable for readability

### Commit Messages
- Use present tense ("Add feature" not "Added feature")
- Use imperative mood ("Move cursor to..." not "Moves cursor to...")
- Limit first line to 72 characters
- Provide detailed description in commit body if needed

### Arabic Content
- Use Modern Standard Arabic (MSA)
- Ensure proper right-to-left formatting
- Use appropriate honorifics and formal language
- Verify cultural appropriateness
- Maintain consistency with existing translations

## 🔒 Security & Confidentiality

### Important Reminders
- Do not include sensitive government information
- Do not share API keys, passwords, or credentials
- Do not include personal contact information
- Follow data protection best practices
- Report security issues privately to maintainers

## 📞 Getting Help

### Questions or Issues?
- Check existing documentation first
- Search closed issues for similar questions
- Open a new issue with "Question:" prefix
- Be specific and provide context
- Be patient and respectful

### Contact
For sensitive matters or official inquiries, use the official UAE government channels as mentioned in the project documentation.

## 📜 Code of Conduct

### Expected Behavior
- Be respectful and professional
- Value diversity and inclusion
- Focus on constructive feedback
- Respect cultural differences
- Maintain confidentiality when required

### Unacceptable Behavior
- Harassment or discrimination
- Offensive or inappropriate content
- Sharing confidential information
- Disrespecting UAE culture or values
- Spamming or trolling

## 🎯 Quality Standards

### Before Submitting
All contributions must:
- Pass the review checklist
- Be reviewed by the contributor
- Include appropriate documentation
- Work on the latest version
- Not break existing functionality

### Testing
- Test your changes locally
- Verify links and references
- Check formatting on different devices
- Validate bilingual content
- Ensure no regressions
